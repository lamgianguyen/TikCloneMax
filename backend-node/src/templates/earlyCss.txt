<style id="tf-nav-early">
  /* Paint a dark canvas from the very first frame so the multiple
     bootstrap reloads (and switchProfile-triggered location.reload())
     don't flash white between renders. Matches Electron's
     backgroundColor #1c1d22 used in main.js. */
  html {
    background: #1c1d22 !important;
    /* Reserve vertical scrollbar space ALWAYS so viewport-width stays
       constant regardless of page content height. Without this, switching
       between profiles with different overlay counts causes the scrollbar
       to appear/disappear, shifting viewport-width by ~15px and crossing
       @media (max-width: 1913px) breakpoints — same window size renders
       at different zoom levels per profile. `stable` reserves the gutter
       even when no scrollbar is needed; `both-edges` keeps centered
       layouts honest. Falls back to standard rendering on old browsers. */
    scrollbar-gutter: stable !important;
  }
  body { background: #1c1d22 !important; color: #e5e7eb; }

  /* Switch-profile loading overlay — covers viewport during the bundle's
     reload chain (typically 8-12 reloads) so the user sees a clean
     loading state instead of UI flicker. Removed after 3s of stability. */
  /* Match the splash and reload-mask exactly so all three loading
     states look identical — solid #1c1d22 canvas, brand spinner image,
     simple title + subtitle. Avoid border-spinner / blue accent which
     visually clashed with the splash and amplified perceived jitter. */
  #tf-switch-overlay {
    position: fixed; inset: 0;
    background: #1c1d22;
    z-index: 2147483647;
    display: flex; align-items: center; justify-content: center; flex-direction: column;
    opacity: 1; transition: opacity 400ms ease-out;
    pointer-events: all;
    font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, sans-serif;
  }
  #tf-switch-overlay.tf-fade-out { opacity: 0; pointer-events: none; }
  #tf-switch-overlay-spinner {
    width: 96px; height: 96px;
    background: url('/img/loading.svg') center/contain no-repeat;
    filter: brightness(1.05);
  }
  #tf-switch-overlay-text {
    margin-top: 18px;
    color: #e5e7eb;
    font-size: 14px;
    font-weight: 500;
    letter-spacing: 0.3px;
  }
  html, body { width: 100% !important; min-height: 100vh !important; overflow-x: hidden !important; }
  #navigation-app.hidden, #pages.hidden { display: block !important; }
  /* Don't force min-height 100vh on inner page containers — bundle's home
     page can be short (just Welcome text) and a forced viewport-height
     leaves a black gap between topbar and Welcome footer. Let content
     flow naturally. */
  #navigation-app, #pages { width: 100% !important; max-width: 100vw !important; }
  /* Some bundle pages (Overlays gallery, Goals) put two wide cards side
     by side that overflow the viewport on narrower windows. Confine
     horizontal scroll to the inner page container so the body stays
     clean and the topbar doesn't bounce sideways. */
  #pages .page.pageenabled { display: block !important; opacity: 1 !important; visibility: visible !important; max-width: 100% !important; overflow-x: auto !important; }

  /* Bundle's own media query at @media(max-width: 1918px) sets
     .greyBackgroundSection min-width: 850px. So at >=1918px the bundle
     expects 2 cards side-by-side (compactPathBox 315px + graphicSection
     730px + gap fits in ~1900px content area). At narrower widths the
     bundle's flex-wrap kicks in and cards stack naturally.
     We do NOT override flex-direction here — that breaks the bundle's
     intended 2-column layout on full HD displays. If a 2nd card runs off
     the right edge it's because the user's content area (after sidebar
     + sub-sidebar) is narrower than the bundle's design assumes; the
     page-level `overflow-x: auto` we set above lets the user scroll. */

  /* === Overlay Gallery layout =============================================
     Bundle ships cards with `width: 780px` + `zoom: 0.9` curve so at HD
     viewport, 2 zoomed cards (702px each) fit the content area after
     sidebar + sub-sidebar. Without zoom (which breaks on resize), the raw
     780px cards × 2 + gap = 1580px overflow the ~1420px content area at
     maximized 1920px window → right card gets clipped, buttons unreachable.
     Fix: use `flex: 1 1 <basis>` so cards STRETCH to fill container at
     wide widths AND wrap cleanly to 1 column when basis can't fit twice.
     `width: auto !important` overrides bundle's 780px so flex sizing
     drives card width instead. */
  .obsOverlayContainer {
    display: flex !important;
    flex-wrap: wrap !important;
    gap: 20px !important;
    zoom: 1 !important;                   /* nuke bundle's broken zoom curve */
    max-width: 100% !important;
    justify-content: flex-start !important;
    align-items: flex-start !important;
    align-content: flex-start !important;
  }
  /* `flex: 0 1 calc(50% - 10px)` = each card wants exactly half the row
     (minus half the 20px gap) — DOES NOT grow beyond that. `min-width: 560px`
     forces wrap when the per-card half drops below 560px. This guarantees:
       - container <  1140px → 1 column (min-width forces wrap, card 100%)
       - container >= 1140px → 2 columns (each ≈ half, no overflow)
       - container >= 1700px → 3 columns (wide monitors get more)
     Critical change from the prior `flex: 1 1 720px`: removing flex-grow
     prevents cards from inflating past their half-share and overflowing
     the right edge — which broke once the sub-sidebar started occupying
     256px on the left, leaving the content area narrower than the old
     basis assumed. `calc(50% - 10px)` adapts automatically to whatever
     space the container has, so the rule stays correct regardless of
     sidebar visibility. */
  .obsOverlayContainer > .graphicSection {
    flex: 0 1 calc(50% - 10px) !important;
    width: auto !important;
    min-width: 560px !important;
    max-width: 100% !important;
  }

  /* === GUEST STATE (tf-logged-out) === */
  /* Hide dropdowns/popups in profile area */
  body.tf-logged-out #navigation-app [class*="dropdown"],
  body.tf-logged-out #navigation-app [class*="Dropdown"],
  body.tf-logged-out #navigation-app [class*="popover"],
  body.tf-logged-out #navigation-app [class*="Popover"] {
    display: none !important;
    pointer-events: none !important;
  }
  /* === TWO TOPBARS: guest (static) vs logged-in (Vue) === */
  #tf-guest-topbar { display: none; position: fixed; top: 0; left: 0; right: 0; height: 48px; z-index: 10000; }
  body.tf-logged-out #tf-guest-topbar { display: block !important; }
  body.tf-logged-out #navigation-app .topbar { visibility: hidden !important; }

  /* === "Getting things ready for you..." splash overlay ===
     While the bundle is bootstrapping (splashScreen still in DOM), cover
     the entire viewport with a solid dark canvas so the half-rendered
     sidebar / topbar / guest-topbar don't peek through. The bundle removes
     #splashScreen itself once init completes, so this CSS auto-disables. */
  #splashScreen {
    background: #1c1d22 !important;
    z-index: 2147483646 !important;
    color: #cbd5e0;
    /* Force full viewport — bundle's own width sometimes shrinks during
       the reload chain, exposing the Electron window background on the
       right. Pin to 100vw/100vh so the dark canvas always reaches the
       edges, matching the smooth final loading state. */
    position: fixed !important;
    inset: 0 !important;
    width: 100vw !important;
    height: 100vh !important;
    margin: 0 !important;
    padding: 0 !important;
  }
  #splashScreen .loadingSpinner { filter: brightness(1.2); }
  #splashScreen .loadingStaticText {
    color: #e5e7eb;
    font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, sans-serif;
    font-size: 14px;
    letter-spacing: 0.3px;
    margin-top: 16px;
  }
  #splashScreen .loadingStatus {
    color: #9ba3af;
    font-size: 12px;
    margin-top: 8px;
  }
  /* Hide sidebar / topbar while the bundle's splash is showing. We toggle
     the .tf-splash-active class on the body element via a MutationObserver
     (defined in blockScript) instead of relying on :has() — :has() matches
     even after the bundle flips #splashScreen to display:none, so the
     sidebar would stay hidden forever. The observer watches for display
     / visibility changes and removes the class as soon as splash is hidden. */
  body.tf-splash-active #navigation-app,
  body.tf-splash-active #pages,
  body.tf-splash-active #sidebar,
  body.tf-splash-active #tf-guest-topbar,
  body.tf-splash-active #tf-topbar-mount {
    visibility: hidden !important;
  }
  /* While the splash is up, kill the body scrollbar entirely. Without this
     the bundle's bootstrap chain causes the page height to jitter (sidebar
     mounts → 100vh, splash overlays → no inner content, etc.) and the
     scrollbar flashes on/off every few hundred ms — visible as a jiggling
     bar on the right edge. `overflow:hidden` while splash is active is
     safe because nothing is interactable anyway. */
  body.tf-splash-active { overflow: hidden !important; }
  html.tf-splash-active { overflow: hidden !important; }
  /* Kill body scrollbar whenever our `#tf-switch-overlay` is present — it
     covers the full viewport so any scroll position underneath is invisible
     anyway, and Vue's bootstrap chain that triggered the overlay also
     swaps the page's scroll height a few times per second, causing the
     bar to flicker. `:has()` is supported in modern Chromium (Electron). */
  html:has(#tf-switch-overlay),
  body:has(#tf-switch-overlay) {
    overflow: hidden !important;
  }

  /* The bundle's profile chip has a sibling preview card — a large `<img>`
     of the connected TikTok account's avatar, anchored `top: 100%` so it
     sits BELOW the chip. The card was meant as a hover preview but renders
     unconditionally in our build (no parent group:hover hook fires), so a
     ~150px square avatar dangles down across the page when the chip is
     present. Hide the misplaced preview — the chip's own SVG (or our
     overlay <img id=tf-chip-avatar>) shows the avatar in-line where it
     belongs. Match the `absolute + top-full` combo (Tailwind utility
     classes) — this combination only exists on dangling-preview <img>s
     in the topbar, not on legitimate UI elements. */
  /* Dynamic match: any <img> sourced from TikTok's CDN AND positioned via
     Tailwind `absolute` utility class. The chip's legitimate inline-styled
     overlay (created by paintTopbarAvatar with `style="position:absolute"`)
     is unaffected because it has no `absolute` CSS class — only an inline
     style. Works for any TikTok username, not hardcoded to one account. */
  img[src*="tiktokcdn"][class*="top-full"],
  img[src*="tiktokcdn"][class*="absolute"][class*="right-0"],
  img[src*="tiktokcdn.com/tos-"][class*="absolute"] {
    display: none !important;
    visibility: hidden !important;
  }

  /* Sub-sidebar items wrapper: the Vue navigation renders page items inside
     .w-64.bg-secondary > .flex-1 > .flex.flex-col.gap-2, but its `v-show`
     directive keeps the wrapper at display:none even when the items are
     fully populated (the section-container, page-item, and item rows all
     exist underneath with the correct active/selected classes). Without
     dev-tools access to the Vue runtime we cannot flip the v-show flag.
     We force the wrapper visible ONLY when it actually contains page-items
     — empty wrappers (guest mode, loading transient, page with no sub-items)
     keep their default hidden state, so this change is scoped and reversible:
       - selector requires .w-64.bg-secondary container → cannot match any
         other Tailwind `.flex.flex-col.gap-2` in the app
       - :has(.page-item) guard ensures we only override when items exist
       - !important overrides Vue's inline display:none cleanly */
  div.w-64.bg-secondary div.flex.flex-col.gap-2:has(.page-item) {
    display: flex !important;
  }
</style>
